# 从零建一个 Go API

笔记 API 就是按这个顺序做出来的。下次新项目照着做，再打开 [`projects/notes-api`](../projects/notes-api/README.md) 对照。

## 1. 建模块和目录

```bash
mkdir my-api && cd my-api
go mod init example.com/my-api
mkdir -p cmd/api cmd/worker internal/handler internal/middleware internal/service internal/repo migrations
```

## 2. 配置不要进 git

`.gitignore` 写上 `.env` 和 `tmp/`。

`.env.example` 只留变量名和假密码，例如 `MYSQL_DSN`、`REDIS_ADDR`、`JWT_SECRET`。真实值放本机 `.env` 或部署环境。

## 3. main 里的组装顺序

1. 读配置
2. 建 logger
3. 连 MySQL
4. 连 Redis
5. 注册路由
6. 监听端口
7. 收到退出信号后，先停掉新请求，再关数据库和 Redis

不要在 `main` 里写业务判断。

## 4. 先做健康检查

`GET /health` 执行一次数据库 `Ping`。这一步通了，再加登录和业务接口。

## 5. 表结构只追加

第一张表是 `migrations/001_init.sql`。以后改表新建 `002_xxx.sql`，不要回头改已经在别人库里跑过的文件。

## 6. 新接口放哪

| 层 | 只做什么 |
|----|----------|
| handler | 解析 HTTP，返回 JSON |
| middleware | 登录校验 |
| service | 业务规则 |
| repo | MySQL、Redis |

路由集中在一个地方注册。

## 7. 登录和慢操作

要登录的路由放进 JWT 分组。发短信、写审计这类慢操作丢进队列，由 `cmd/worker` 消费，不要写在 handler 里。

## 8. 本地热更新

复制 `.air.toml`，把编译命令改成：

```toml
cmd = "go build -o ./tmp/main ./cmd/api"
bin = "./tmp/main"
```

在项目根目录执行 `air`。worker 另开一个终端跑。
